# Image editing and galleries (Figma L) — implementation plan

Figma: section **L · Images**, page « Editor — Behaviors »
(https://www.figma.com/design/Y3vDuuW4jfyTOjreIwDp6P/OutilsEnLigne.ca?node-id=193-11208). Decisions: L5, 5 Oct 2026.
Overview and order of work across K–N: `docs/plans/2026-10-k-to-n-overview.md`. Supersedes restructure Phase 8's
« oelimg-rs → crates/oel-img » line (`docs/plans/2026-10-restructure.md`).

## Decisions

- **Engine: wgpu, shared.** New crate `crates/oel-img`, WGSL shaders. Web: WASM in a worker on an `OffscreenCanvas`,
  WebGPU first, WebGL2 fallback (wgpu's GL backend). Tauri app: the same crate natively (Vulkan / Metal / DX12). Preview
  and export are the same passes; `oelimg-rs`'s algorithms become the CPU reference (tests, no-GPU fallback, server).
- **Non-destructive.** An image = original bytes (content-hashed, never changed) + a versioned recipe
  (`oel-img-recipe@1`). The recipe lives in Yjs; the original in the project's media store.
- **Two tabs, one recipe.** Simple (styles, Auto, Lumière, Couleur, Cadrer) and Avancé (Base, Présence, Courbe des
  tonalités, Mélangeur TSL, Étalonnage, Détail, Optique et géométrie, Effets). Simple sliders are macros over Avancé fields.
- **Galleries are a desk object that works like a folder.** « Modifier les images » on a multi-selection of images
  creates a gallery planche containing them. Inside, images are placed and **resized freely** (no grid); the gallery's
  style applies to all, each image may keep its own overrides on top (amber dot). Dragging an image out removes it from
  the gallery. An image belongs to at most one gallery.
- **Every desk item becomes resizable** (generic desk feature, see L-5).
- **Placed elsewhere, it follows.** A gallery image placed in a document, slide or sheet is a link (`@oel/links`,
  carries `picture`): live / manual / frozen like charts; crop and size stay local to the copy.
- **Same atelier in the editors.** Selecting a picture in docs / slides / sheets shows « Retoucher » in its floating bar;
  the panel opens inside the editor. For a linked gallery image the scope switch offers « Cette copie » / « Style de la
  galerie (N) ».
- **Office files** get the final pixels; original + recipe ride along in an OEL custom part (ignored by Office) so a
  file reopened in OEL stays editable. If the visible image changed outside OEL (hash mismatch), it becomes the new base.
- **Masks / local retouching after v1** (brush, linear/radial gradients, then subject/sky via ONNX on GPU). Panel shown
  greyed « Bientôt ». Styles (presets) are stored **per project** (N).

## Recipe v1 (`oel-img-recipe@1`)

Rust structs in `oel-img/src/recipe.rs` (serde + ts-rs → `packages/engine/src/generated/`, Phase 2 pattern):
- `white_balance { temp_k, tint }`, `exposure`, `contrast`, `highlights`, `shadows`, `whites`, `blacks`
- `presence { texture, clarity, dehaze, vibrance, saturation }`
- `tone_curve { rgb, r, g, b: Vec<[f32;2]> }` (monotone cubic → 1D LUT)
- `hsl: [ { hue, sat, lum }; 8 ]` (red, orange, yellow, green, aqua, blue, purple, magenta)
- `grading { shadows, midtones, highlights: { hue, sat, lum }, blending, balance }`
- `detail { sharpen { amount, radius, detail, masking }, noise { luma, color } }`
- `effects { vignette { amount, midpoint, roundness, feather }, grain { amount, size, roughness } }`
- `geometry { crop: [x0,y0,x1,y1] (normalised), angle, flip_h, flip_v, aspect }`
- Layering: `effective = image_overrides ⊕ gallery_style ⊕ defaults`, per field (`Option<T>` everywhere).
- Yjs: one `Y.Map` per recipe, one key per leaf field (last-writer-wins per slider, collaborative).

## Pipeline (all passes are render passes so WebGL2 works)

decode (browser `createImageBitmap` / `ImageDecoder`; native: `image` crate) → EXIF orientation + ICC → linear
working space (linear Rec.2020 / ACEScg-like, f16 textures) → white balance + exposure → tone (highlights/shadows via a
blurred-luminance base layer; whites/blacks) → tone curve LUT → HSL mixer → colour grading → presence (texture/clarity
as multi-scale detail; dehaze; vibrance/saturation) → detail (unsharp/guided denoise) → effects (vignette, grain) →
geometry (crop/rotate/flip in the final sampling pass) → output transform to sRGB / Display-P3 → screen or tile.
Histogram: compute shader on WebGPU/native, readback of a 256-px proxy on WebGL2. Preview renders at screen size
(target 60 fps while dragging); export renders full resolution in 2048-px tiles with overlap for blur kernels.

## Phases (each ends with typecheck + tests + a commit)

### L-1 · `crates/oel-img` from oelimg-rs (CPU reference)
- Move oelimg-rs into the workspace (history via subtree if wanted), bump `image`, drop `resvg` unless needed, add
  `feature = "wasm"`. Recipe structs + serde + ts-rs. CPU reference pipeline in `cpu/` (f32, linear), reusing oelimg-rs
  colour/curve/HSL/blur code. Fixtures `fixtures/img/` (portrait, landscape, high-key, low-key, saturated, PNG with alpha).
- cargo tests: identity recipe = input (±1/255), per-control monotonicity, recipe JSON round trip.

### L-2 · GPU pipeline (native first)
- `gpu/` with wgpu; WGSL per pass; `Renderer::{new, set_source, set_recipe, render(view|tile), histogram}`.
- Tests on a software adapter (lavapipe / WARP when available, skipped with a message otherwise): GPU vs CPU max
  per-channel diff ≤ 2/255 on fixtures for each control.

### L-3 · Web transport
- `wasm` build (`npm run build:wasm` picks it up), worker that owns the `OffscreenCanvas`; `@oel/img` package:
  `ImageEngine` host (like `EngineHost`), capability probe (WebGPU → WebGL2 → CPU fallback via oel-img CPU in WASM,
  with a notice « Aperçu ralenti : processeur graphique indisponible »).
- Media store seam: originals by content hash (reuse `@oel/links` `pictures.ts` hashing); in-browser cache now,
  `@oel/platform` / server `domains/media` when restructure Phases 4–5 land.

### L-4 · Atelier on image papers (Simple / Avancé)
- `@oel/img/ui`: `Atelier` (full screen, level 3 for images), `AtelierPanel` (histogram, tabs, scope switch, groups,
  sliders from `@oel/emboss` — double-click resets, arrows ±1, Maj ±10), before/after (`\` held), copy/paste settings,
  undo/redo through Yjs `UndoManager`, export dialog (JPEG/PNG/WebP, size, quality).
- Replace `ImageWorkspace` (`apps/web/src/bureau/workspaces/SimpleWorkspaces.tsx`); thumbnails rendered with the recipe.
- Icons: `magic-wand`, `media-image-list` (gallery) added to `@oel/emboss` (already in Figma).

### L-5 · Desk: resize everything + containers (generic `@oel/desk`)
- `store.resize(id, rect, { keepAspect })`, handles in `DeskCanvas` (corners + edges, Maj keeps aspect, Alt from
  centre), min sizes; keyboard: Alt + Maj + arrows resizes. Per-kind policy supplied by the app (`resizeMode:
  'scale' | 'free' | 'aspect'`): documents/slides/PDF scale their thumbnail, images keep aspect, notes free.
- Containers: `DeskNode.parent?: string` with child coords local to the parent; enter a container (double-click) to
  select/move/resize its children; Échap leaves; drag a child out to unparent, drag onto a container to parent.
  Hit-testing, ordering, minimap and selection outlines respect parents. No file-type knowledge in the desk.
- vitest: resize with/without aspect, parent/unparent round trips, undo.

### L-6 · Galleries (new kind `gallery`)
- Kind module (restructure Phase 3 if landed, else the current `bureau/` switches): label « Galerie », icon gallery,
  planche rendering (title, style chip, children drawn by the desk), context toolbar Retoucher · Étaler les images ·
  Exporter · ….
- Desk context menu on images-only selection: « Modifier les images (N) » / single: « Retoucher l’image ». Creates the
  gallery around them (children keep relative positions), opens the atelier with the filmstrip and scope switch
  « Style de la galerie / Cette image » (default: gallery).
- Data: gallery `PaperData.gallery = { style: RecipeRef, name }`; image `PaperData.image = { media: hash, recipe }`.

### L-7 · Inside the editors
- Docs: Tiptap `image` node attrs gain `recipe` (+ `orig` hash); NodeView renders through `ImageEngine` (bitmap cache
  keyed by hash + recipe rev). Slides: `picture` element facet `recipe`. Sheets: picture drawings `recipe`.
- Floating image bar: Retoucher · Recadrer · Remplacer · Habillage (docs) · Texte alternatif; « Retoucher » opens
  `AtelierPanel` docked right inside the editor (pushes the page like the links panel).
- Codecs (`oel-docx`, `oel-pptx`, `oel-xlsx` via `oel-opc`): write rendered pixels to the media part; custom part
  `/oel/img/<hash>.json` (recipe) + original bytes under `/oel/media/`; reader restores when the visible media hash
  matches the recorded output hash. Round-trip tests per codec.

### L-8 · Gallery images as links
- `SourceRef { kind: 'image', objectId }` resolves gallery members; `LinkedValue.picture` gains `recipe` (gallery
  style ⊕ image overrides). Local edits (crop/size) stay on the copy (`LocalEdit`). « Cette copie » vs « Style de la
  galerie » in the editor panel writes to the right place.

### L-9 · Desktop (with restructure Phase 7)
- Tauri commands `img_render`, `img_export` on the native crate; `@oel/platform/tauri` transport. Measure 24 MP export
  native vs WASM.

Later: masks (brush, gradients, subject/sky ONNX), RAW (rawler) and HEIC read, lens profiles, video reuse of galleries.

## Verification
- cargo: CPU/GPU parity, recipe round trip, codec round trips (L-7).
- vitest: recipe layering, Simple→Avancé macro mapping, Yjs binding, desk resize/containers.
- Browser (one attempt): open image → Simple/Avancé → export; select 3 images → gallery → style → per-image override;
  move/resize inside the planche; link a gallery image into a doc, change the style, copy updates; retouch a picture in
  docs/slides/sheets; WebGL2 path (WebGPU disabled).

## Status
- **L-1 done** (5 Oct 2026, branch `feat/images`). `crates/oel-img` is a rewrite in linear light rather than a move:
  oelimg-rs works on 8-bit gamma values with `JsValue` errors, so only its ideas (HSV, Kelvin, separable blur) carried
  over; oelimg-rs stays as the old site's npm package. Recipe layers (`Option` leaves, `over` / `resolve`), `fields()`
  table → generated `oelimg/fields.ts`, CPU pipeline with every pass constant in `cpu/pipeline.rs` and the shared blur
  spec in `cpu/blur.rs` (halve while σ > 6), `decode` feature (EXIF orientation, ICC via moxcms), `wasm` feature
  (`render_rgba`, `stack_recipes`). Synthetic fixtures in `fixtures/img/`. `cargo run -p oel-img --release --example
  render -- <img> '<recipe>' out.png` renders one recipe for eyeballing.
- Choices made in L-1 (change here if wrong): temperature is relative to 6500 K (no « as shot » for non-RAW);
  geometry is applied in the final pass, so vignette and grain follow the crop; grain is tied to original-resolution
  pixels so a proxy and the export match; tone curves are composed into one 1024-entry LUT per channel.
- **L-2 done** (5 Oct 2026). `gpu/` behind feature `gpu` (wgpu 30): one WGSL module, one fragment entry per pass,
  `textureLoad` only. Intermediates are RGBA16F (RGBA32F is not renderable on GL/WebGL2) **stored in linear-sRGB
  primaries** and converted to Rec.2020 in each shader (f16 in Rec.2020 lost near-black channels to cancellation in
  the output matrix: diff 3/255); scalar planes are RG16F value + rounding residual (dehaze divides by them). Parity
  ≤ 2/255 on 6 fixtures × 21 recipes on lavapipe, Intel Iris Xe and RTX 4060 (Vulkan) and Mesa GL (the WebGL2-like
  path, `WGPU_BACKEND=gl`; NVIDIA's EGL can't create a headless GL device here). `tests/shader.rs` validates the WGSL
  with naga without a GPU. Histogram = readback of a ≤ 256-px rendering + CPU bins on every backend (no compute
  shader; one path). Examples: `gpu_info` (adapters, renderable formats), `gpu_bench`.
- Measured at 2400 × 1600: RTX 4060 1.3 ms (light recipe) / 6.5 ms (everything on); Iris Xe 14.5 / 127 ms (≈ 3 ms per
  full-resolution pass, ≈ 10 ms per small-σ blur). For 60 fps on integrated GPUs, L-3/L-4 should render a half-size
  proxy while a slider is dragged and the full preview on release; fusing per-pixel passes is the next optimisation.
- Not yet: tiled export beyond `max_texture_dimension_2d` (sources larger than the limit are refused with a message;
  WebGL2 guarantees only 2048, so L-3 must tile or proxy).
- **L-3 done** (5 Oct 2026). `GpuView` (wasm) draws into the transferred `OffscreenCanvas`: WebGPU through
  `new_instance_with_webgpu_detection`, else WebGL2 (adapter requested with the surface); a scratch-canvas probe first,
  so a failure leaves the real canvas free for the CPU path's 2D context. Web wasm 2.5 MB (`wasm,gpu`), node wasm
  (`wasm`) for vitest. `@oel/img`: `ImageEngine` (main thread; `createWorker` injected, `apps/web/src/bureau/images.ts`),
  worker = thin glue + `createImageHandler` (platform calls injected, tested with the CPU backend), proxies (preview
  ≤ 2560 px, half-size while dragging), draws coalesced (a waiting draw is answered `skipped`), export = GPU at full
  resolution when the original fits the device, else the CPU reference (tiled GPU export still later), `raster` for
  thumbnails, `SLOW_PREVIEW_NOTICE` on the CPU path. Recipe helpers in TS (`stackRecipes` checked against Rust,
  `getLeaf` / `setLeaf` / `leafValue` / `outputSize`). Originals by content hash (`contentHash` now exported by
  `@oel/links`) in IndexedDB through `originals()`, replaceable with `setOriginalStore`.
- Browser (Firefox, Linux — no WebGPU): WebGL2 path renders, draws in 3–18 ms at 1200 × 800, histogram, JPEG export at
  full crop resolution. Fixes found there: `@oel/img` must not import `@oel/collab-client`'s index (React UI; new
  `@oel/collab-client/local` entry), and WebGL2 readback needs polling plus a macrotask yield (`gpu/readback.rs`).
  Confirmed by the user in Chrome (WebGPU) and Firefox (WebGL2): full draw 1.7 ms / 2.0 ms, JPEG export 77 ms / 45 ms
  (1440 × 960).
